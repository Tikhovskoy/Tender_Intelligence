# Логика решения

## Загрузка и извлечение текста

Файл читается порциями, поэтому размер проверяется до накопления всего содержимого в памяти. Сервис проверяет имя, MIME-тип, сигнатуру `%PDF-` и установленный предел. Запись сначала ведётся во временный файл, а после успеха атомарно завершается переименованием.

PyMuPDF извлекает текст отдельно для каждой страницы. Пустые страницы допустимы, но документ без извлекаемого текста переводится в `failed` с понятной причиной. OCR намеренно не входит в текущую версию.

## Разбиение документа

Чанки никогда не пересекают границу страницы. Алгоритм стремится завершить фрагмент на границе абзаца, строки или предложения и использует перекрытие, чтобы не потерять смысл на стыке. Для каждого фрагмента сохраняются:

- номер страницы;
- глобальный последовательный индекс;
- начало и конец в тексте страницы;
- текст и, при наличии провайдера, embedding с именем модели.

## Карточка тендера

Перед обращением к LLM весь документ не отправляется. Эвристический селектор ищет фрагменты по группам ключевых слов для названия, заказчика, цены, сроков, требований и санкций, после чего соблюдает ограничения по числу чанков и символов.

Провайдер получает строгую JSON-схему Pydantic. Каждое найденное поле обязано иметь номер страницы и короткую цитату. Значение без подтверждения заменяется на `не найдено в документе`. Перед сохранением приложение нормализует пробелы и проверяет, что каждая цитата действительно присутствует в переданном контексте.

## Векторный поиск и ответы

Вопрос преобразуется в embedding той же модели, которой проиндексирован документ. PostgreSQL выбирает top-k чанков одного документа по cosine distance. Результаты ниже порога релевантности отбрасываются.

LLM получает только вопрос и найденные фрагменты. Приложение самостоятельно формирует доверенные источники из строк БД, поэтому провайдер не может подменить номер страницы или цитату. Для подтверждённого ответа требуется не менее двух источников; при недостаточном контексте возвращается стандартная фраза `Ответ не найден в документе.`

## Ошибки и устойчивость

Ожидаемые ошибки имеют безопасный код и русское сообщение. Ошибка загрузки удаляет незавершённый файл. Ошибка извлечения или индексации сохраняется в документе со статусом `failed`. Недоступность внешнего провайдера не останавливает приложение: список документов, загрузка и извлечение продолжают работать, а пользователь видит локальное сообщение об ошибке.

## Проверки

Тесты используют репозитории в памяти и управляемые провайдеры, поэтому ключевой набор не требует API-ключа или сети. Покрыты правила загрузки, извлечение, chunking, схема карточки, проверка цитат, ранжирование источников, недостаточный контекст, JSON API и HTML-сценарии.
