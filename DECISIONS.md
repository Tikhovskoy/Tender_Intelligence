# Архитектурные решения

## ADR-001: модульный монолит

Выбран один FastAPI-сервис с явными слоями. Для демонстрационного проекта это уменьшает эксплуатационные расходы, сохраняя границы, по которым обработку можно вынести позднее.

## ADR-002: PostgreSQL и pgvector как единое хранилище

Метаданные, текст, карточки, история и векторы находятся в одной БД. Это даёт транзакционность и не требует отдельного векторного сервиса. Компромисс — при очень больших объёмах потребуется настройка индексов и отдельная стратегия масштабирования.

## ADR-003: локальные фоновые задачи без очереди

После загрузки обработка запускается через `BackgroundTasks`. Решение соответствует ограничению одного сервиса и удобно для локального показа. Оно не гарантирует продолжение задания после перезапуска процесса; производственная версия потребует очереди и идемпотентного восстановления зависших статусов.

## ADR-004: источники проверяет приложение

Карточка проходит проверку цитат по переданному контексту, а источники ответов строятся из найденных строк БД. Это снижает риск неподтверждённых страниц и фрагментов. Проверка является текстовой и не заменяет экспертную оценку документа.

## ADR-005: Jinja2 и HTMX без фронтенд-сборки

Серверные шаблоны достаточны для MVP и сокращают число инструментов. HTMX хранится локально, поэтому интерфейс не зависит от CDN. При усложнении клиентского состояния можно пересмотреть подход, не меняя JSON API.

## ADR-006: OpenAI-совместимый контракт провайдера

Один транспорт поддерживает облачную точку доступа и Ollama. Модели и адрес задаются окружением. Конкретные ответы могут различаться между моделями, поэтому итог всегда валидируется доменными схемами.
